Activation no longer needs the guard summary acknowledged. The review shows the guard summary as one line, such as "8 will start, 2 skipped (1 contacted in the last 30 days, 1 no email)", and **Show skipped contacts** lists each skipped contact with every reason, up to 500. "Will start" counts the contacts the guards let through for the first step; each later step is checked again when it fires. Of two pending enrollments that share an address, the summary skips only the newer one, as the engine does. When the old tool already emailed some of the contacts that will start, a note says how many and when it last did. The summary gates nothing: the guards still check every contact again when each step fires, so a contact they exclude then is never sent anything. Every other requirement is unchanged: step approvals, a clean lint, a test of each email step, a healthy mailbox, and the scheduled start. The API drops `POST /campaigns/{id}/review/guards/acknowledge` and `guards_acknowledged` from `GET .../review`, adds `prior_contact_note` there, and adds `GET .../review/guards` (with `limit`, at most 500) for the details. The CLI adds `netkeeper campaigns guards` (with `--limit`), and `campaigns activate` prints the summary and the note before it asks. The enroll answer's `summary` uses the new wording.
