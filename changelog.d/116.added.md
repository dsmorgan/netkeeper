`GET /api/v1/contacts/stats` (`netkeeper contacts stats` had it already) puts the triage counts a dashboard needs behind the API, from the one function, `contact_stats()`, that also backs the triage queue's progress bar — a parity test pins the endpoint, the CLI, and `triage.progress()` to the same numbers so the three cannot quietly disagree again the way the CLI and the API once did (#85). The stats now also carry `tagged_by_rule`, a contact an auto-tag rule tagged, alongside the existing `tagged` (any source) — the two answer different questions and neither is inferable from the other. A draft `import_run` that a `--dry-run` or a refused commit leaves behind is no longer invisible: `GET /imports?status=draft` (`netkeeper import runs --status draft`) lists them and `DELETE /imports/{id}` (`netkeeper import rm`) removes one, scoped to the caller and refusing a committed or rolled-back run. `netkeeper import resume <id>` finishes a draft in place — re-resolving every row against the database as it is now, the same way `commit()` always has, rather than trusting the resolution a possibly-stale draft recorded — on the same `POST /imports/{id}/commit` path the web wizard's "Finish this import" already used, so a run a refusal named is the one that gets finished, not a second draft orphaning it (#90).
