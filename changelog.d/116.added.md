`GET /api/v1/contacts/stats` (`netkeeper contacts stats` had it already) puts the triage counts a dashboard needs behind the API, from the one function, `contact_stats()`, that also backs the triage queue's progress bar — a parity test pins the endpoint, the CLI, and `triage.progress()` to the same numbers so the three cannot quietly disagree again the way the CLI and the API once did (#85). A draft `import_run` that a `--dry-run` or a refused commit leaves behind is no longer invisible: `GET /imports?status=draft` (`netkeeper import runs --status draft`) lists them and `DELETE /imports/{id}` (`netkeeper import rm`) removes one, scoped to the caller and refusing a committed or rolled-back run. The CLI's refusal for undecided candidates now names `netkeeper import resume <id>` instead of telling you to re-run `import csv`, which used to read the file into a second draft and orphan the one the message had just named; `import resume` finishes the named run in place, on the same `POST /imports/{id}/commit` path the web wizard's "Finish this import" already used (#90).
