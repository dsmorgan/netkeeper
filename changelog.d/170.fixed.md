Six follow-ups from the final review of #168. `netkeeper linkedin clear-flag` no longer holds the write lock across its confirmation prompt: it reads the flag, asks, and only then opens a writer, clearing it only if it is still the exact flag the prompt showed -- a concurrent writer (`netkeeper serve`, say) no longer sees "database is locked" for however long a person takes to answer. `netkeeper preflight` reads a `Checkpoint` flag to report on it the same way, without ever taking a write lock just to look. Both the preflight success line and the `clear-flag` docstring stop claiming "LinkedIn accepted this session" or "answered again" -- preflight only ever reads this Chrome profile's own cookie jar (spec 9.1), so the wording says that instead. The in-page Voyager fetch script now checks `location.origin` a second time, from inside the page, atomically with the rest of what it does, closing the gap between the Python-side `page.url` check and the script actually running (a tab is free to navigate in between). `PageVoyagerFetch` now strips a caller-supplied `csrf-token` header case-insensitively before building the request -- a header spelled `CSRF-Token` used to slip past the merge and land in the fetch's `Headers` object combined with the page's own live value, rather than overridden by it. `tests/smoke/test_fetch_smoke.py`'s teardown now expires its fixture cookie by navigating the tab to the expiring route instead of an `httpx.get`, which never reached Chrome's own cookie jar in the first place.
