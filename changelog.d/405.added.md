An enrichment run now keeps why each unreadable or mismatched visit could not be read: the visit's number, the contact, and a fixed reason code such as `overlay_never_answered` or `contact_info_control_missing`, never anything from the page. Each distinct unreadable path in the profile reader has its own code. A run that a profile's status stops at once as `route_changed` names that visit and its code too (`profile_status`). The LinkedIn page shows each run's id in the runs list, opens a run's detail when you click anywhere on its row, and lists the reasons there with a link to each contact, along with a connections sync's lost answers. `netkeeper linkedin run <id>` prints the same reasons, `netkeeper linkedin unreadable --since 14d` groups them by contact and code across runs, and `GET /api/v1/linkedin/runs/{id}/diagnostics` serves them. The unreadable limits and the visit itself are unchanged.
