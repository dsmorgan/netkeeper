CLI counterparts to import, export, and triage stats (P1-16). `netkeeper import archive <path>` drives `netkeeper.crm.archive` over a zip, an unpacked directory, or a single CSV, and reports connection rows created/updated/skipped/needing review, message rows and how their conversations were attributed, and invitation rows, with the interactions each added. `netkeeper import csv <path>` drives `netkeeper.crm.import_runs`: `--preset` or `--mapping` chooses the columns, `--dry-run` resolves the whole file and reports without committing, and reading the file and committing it are two separate transactions, the way `POST /imports` and `POST /imports/{id}/commit` are two separate requests, so a run that is refused still leaves a draft behind to open or resume. A row that matches more than one contact is refused by default, naming the rows and the run; `--on-candidate skip` leaves those rows out and `--on-candidate new` gives each its own contact. There is no `--on-candidate merge`: `Candidate.contact_ids` is ascending by id, not ranked by confidence, so a blanket flag would merge into whichever contact happens to be oldest rather than the one that is actually the same person, and merging is exactly the mistake identity resolution exists to prevent. `netkeeper import rollback <run-id>` undoes a committed run and reports what it deleted and restored; a run a merge has since drawn a contact into is refused with the contact's id and told to undo the merge first, never a traceback. `netkeeper export` drives `netkeeper.crm.exports` with the same presets, formats, filter, and sort as `GET /api/v1/exports`, streaming to `--out` or to stdout one chunk at a time rather than building the file in memory. `netkeeper contacts stats` is new: total, met, not met, skipped, untriaged, archived, merged away, and how many carry an email, a phone, or a tag.
