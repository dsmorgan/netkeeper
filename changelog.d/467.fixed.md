With two data directories sharing one database through `NETKEEPER_DATABASE_URL`, one directory no longer marks the other's live LinkedIn run `failed` and starts a second run on the same Chrome. A live run now refreshes a heartbeat on its row every 20 seconds, along with a hash of the host and data directory that runs it (`sync_runs.heartbeat_at` and `heartbeat_by`, migration 0041). Another directory treats the run as left behind only two minutes after its last heartbeat, so a run whose process really stopped is still recovered. Within one data directory nothing changes: a run left by a crashed `serve` is recovered at the next start. `netkeeper linkedin cancel` and `pause` on another directory's run say to stop that directory's netkeeper process if the run doesn't stop.
