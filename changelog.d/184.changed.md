During a LinkedIn API outage, the connections sync's page-reading fallback no longer drops a connection netkeeper has never seen. A card whose link matches no contact now creates one contact marked **needs review**, with the card's name and headline at the lowest provenance and no LinkedIn id, so any later sync or import replaces them. A card name that isn't a name (the link's "View … profile" label, or the name and occupation run together) is refused, and the contact is named by its link instead. Confirm or reject it on the triage card or the contact page; reject archives it and never deletes it. A later sync that matches it by LinkedIn's own id attaches the id and confirms it. Until then, netkeeper never enriches it, enrolls it in a campaign, puts it in a `campaign-audience` export, or counts it as a connection when aging. A card for a contact netkeeper already holds still only counts as a sighting, and a run that fell back is still never complete. Migration 0014 adds `contacts.needs_review_at`.
