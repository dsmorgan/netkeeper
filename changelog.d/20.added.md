Exporters (`netkeeper.crm.exports`, spec 10.6): `GET /api/v1/exports` streams contacts as CSV, JSON, or vCard 4.0, respecting the same filter and sort the contacts table and smart lists use. Four presets: `nine-column` (with a `headerless` CSV variant), the eight columns of Appendix A in order, whose CSV form round-trips through `netkeeper`'s own nine-column importer unchanged; `linkedin-archive`, the columns of LinkedIn's own `Connections.csv`; `full`, every user-facing field including children (emails, phones, links, positions, tags); and `campaign-audience`, the campaign engine's merge fields plus the recipient email, which never includes a `do_not_contact` person. Every preset strips database ids, foreign keys, and sync-internal bookkeeping columns; `nine-column` and `linkedin-archive` also drop a row with nothing identifying a person (no LinkedIn URL, no name, no email, no phone) and a phone number with no digits, since the importer would refuse both anyway. Rows are fetched in bounded batches and written by a generator, so a large export never sits in memory as a whole file or result set, and the request never takes the SQLite write lock, since an export is a read.
