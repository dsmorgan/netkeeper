A LinkedIn run no longer fails when Chrome can't return the body of an answer the page loaded. netkeeper logs the cause as a class name and a fixed category, never the exception's message.

- **Connections sync:** netkeeper keeps scrolling so the page can ask for the lost answer again. If the page moves past it, or the answer still hasn't been read after six more scrolls, the run stops as an incomplete `answer_lost` run. Its note names the start index. Nothing is aged, and the stop doesn't count toward the route-changed breaker.
- **Enrichment:** a lost profile screen or Contact info answer makes that visit unreadable. It counts toward the same limits as any unreadable visit, and the run's note names the visit and the cause. After a lost Contact info answer, netkeeper doesn't click again. A lost lazy card is skipped. A profile page that never finishes loading, because its navigation timed out, is an unreadable visit too, and netkeeper doesn't retry it. A checkpoint or login wall on the tab still stops the run.

A run that fails inside its runner is now recorded only once.
