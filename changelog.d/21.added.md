Contacts table and detail page (spec 10.1, 14.3). `/contacts` is a dense table whose whole state — the filter, the sort, the page — lives in the URL, so a view is a link you can paste and the back button walks your filters. Free text, company, met state, tags, do-not-contact, and archived compile to the filter tree `POST /contacts/query` takes, so filtering, sorting, and paging all happen on the server; the filter box is debounced and local to itself, so typing re-renders no rows and asks the server once. The column picker offers every scalar column the API can return and is remembered per browser, and a query asks only for the columns on screen, so hiding a column stops it crossing the wire. Saved views are P1-08's `/views`: saving one stores the columns, sort, and filter under a name and applies it; applying one reads its filter back into the filter bar where the bar can say it, and uses the stored tree verbatim where it cannot. Row actions cover spec 10.1's list in full — tag, add to list, set met, set do-not-contact, archive, open on LinkedIn, open in Gmail. Adding to a list offers the static lists P1-08 delivered and puts the contact on one through `POST /lists/{id}/members`; a smart list is shown unavailable, because its membership is its filter and the API refuses members for one. Pinning for enrichment is the one action still shown unavailable with a reason rather than as a click that fails: `/linkedin/pins` does not exist yet. Bulk actions go through the confirmation flow: the dialog settles the whole sentence (including a do-not-contact reason, which the token binds), asks `POST /contacts/bulk/count` for the count, shows the server's own reading of the selection, and sends the token back; a count that moved, or a confirmation that expired, is explained in those words, says that nothing was changed, and offers to count again. `/contacts/:id` shows the fields, children, tags, timeline, and snapshots. A LinkedIn field edited by hand is marked a manual override and says what the sync last reported; reverting is a button next to it, and a field no automated source ever reported shows that button disabled with the reason instead of failing after the click. A merged-away contact is handled the way the API defines it: following its id says you were brought to the survivor, and a write that answers `409 merged` becomes a link to the contact to make the change on. A page longer than sixty rows renders a window rather than every row, sized to the viewport plus an overscan on each side; `src/test/contacts-performance.test.tsx` asserts that window exactly at ten thousand rows and after a scroll, that selecting one row re-renders one row, and that five keystrokes a half-debounce apart reach the server as one query and re-render no rows at all. New: `GET /api/v1/contacts/{id}/tags` lists a contact's tags, which the detail screen needs and nothing exposed before.
