Scheduled connections runs now stop after three runs in a row end `answer_lost`. A lost answer moves neither heat nor the route-changed breaker, so before this change a page whose answers kept arriving unreadable would cost page views on every scheduled fire. The count is separate from the route-changed breaker and shows in `netkeeper linkedin schedule status` and in the posture report as the "answer-lost limit". A connections run that completes with nothing lost clears it, and so does `netkeeper linkedin schedule reset-breaker`, which now clears both counts. Manual runs are never refused.
