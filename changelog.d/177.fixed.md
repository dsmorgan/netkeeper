A run now stops when its row is no longer `running`, and cancelling a run that looks left behind still sets its cancel flag, so two data directories sharing one database through `NETKEEPER_DATABASE_URL` can no longer leave a run going after the other marked it failed. The server now answers `421` to a `Host` header containing `@`, `/`, `?`, `#`, a backslash, or whitespace, or with a port that is not a number from 1 to 65535. A run that loses Chrome partway through now records `browser_unavailable` instead of `error`. The configuration docs now explain that with `web.host = "0.0.0.0"`, a request to the machine's LAN address gets `421`.
