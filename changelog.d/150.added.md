`netkeeper.linkedin.fetch.PageVoyagerFetch`: the `VoyagerFetch` implementation `voyager.py` was written to and never itself provided, wired to the page a `BrowserRun` holds. Every call runs a real `fetch()` inside that page via `page.evaluate`, carrying exactly the headers `build_headers` produces built fresh from the live `JSESSIONID` cookie (read over CDP the same way preflight reads cookie names, never logged, returned, or put in an exception message) -- so a Voyager request looks, to LinkedIn, exactly like one the real web client made. Every real call is fixed to `https://www.linkedin.com`; the constructor refuses anything else that is not this machine's own loopback, so no config value or flag can point a run at an arbitrary host, and the opt-in smoke suite still exercises the class against a served fixture on 127.0.0.1. `parse_ok(response, parser)` is the one obvious way to hand a fetched response to a parser: it classifies first (spec 9.7) and raises `VoyagerNotOk` -- carrying the outcome -- for anything other than `Ok`, so a checkpoint interstitial or a login wall's HTML can never reach a parser that was never written to expect one.
