Frontend for tags, auto-tag rules, lists, the filter builder, and exports (spec 10.3, 10.4, 10.6). `/lists` now holds three tabs — lists, tags and their rules, and saved views — and `/exports` holds a selection and a preset picker; both are built on the generated client, with no hand-written request or response type anywhere in the feature. The visual filter builder produces the filter language's own JSON tree, so what it shows is what a smart list stores and what an export runs, unchanged. **Every one of the language's 27 predicates is reachable from it**, and the three the compiler still refuses — `list_member` (issue #73), `enrolled_in` and `replied_in` (P3-04) — are listed as visibly unavailable with the reason rather than quietly left out; two tests hold that line, one comparing the builder's catalog with the discriminator mapping in `frontend/openapi.json` and one (`tests/test_filter_builder.py`) comparing it with `filters.OPS` and `filters.PLACEHOLDERS`, so the builder cannot fall behind the language and a placeholder cannot graduate without the UI noticing. The rule editor counts matches live through `POST /autotag-rules/preview` as the pattern is typed: a pattern the server refuses (a nested unbounded repeat, or counted repeats multiplying past 1000) renders the server's own sentence, and a non-zero `timeouts` is shown beside the count, because searches that hit the 50 ms budget count as no match and the number would otherwise understate. The export dialog offers the four presets and three formats and says what each one costs where it is chosen: `nine-column` round-trips the file, not the contact, since "First Name" carries `preferred_name` out and lands in `first_name` coming back; `campaign-audience` leaves out everyone marked do-not-contact, so its row count is meant to sit below the list's. A static list gets no export button at all, because the predicate that would select its members is the one that does not compile. Smart list membership is read live and never cached across a filter edit, and bulk actions go through the count-confirmation token, re-counting instead of erroring when the selection moves.
