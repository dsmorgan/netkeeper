Rolling back an import is now refused, with nothing undone, when a later import wrote over the same fields (roll the later one back first, newest first), and when contacts the import created have since gained interactions, tags, list memberships, edits or later changes; the refusal says what would be lost, and **Delete them anyway and roll back** in the app (or `netkeeper import rollback --force`) goes ahead. Each refusal carries a `code` so the run page gives the right advice. Committing a large import also reads each matched contact's details in a few queries rather than several per row.
