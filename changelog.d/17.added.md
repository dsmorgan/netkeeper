Lists and saved table views (spec 10.1, 10.4). Migration `0006` adds `lists` (a name unique per user, a `kind` of `static` or `smart`, and a filter tree for a smart list, refused at write time unless it is valid and compiles), `list_members` (explicit membership with an `added_at`, for a static list only), and `saved_views` (a named column set, sort, and optional filter for the contacts table to restore). `netkeeper.crm.lists` creates, renames, and deletes lists; adds and removes a static list's members; and answers a page of any list's members and its count, live: a smart list is never materialized, so its members are always exactly what `netkeeper.crm.filters.compile_filter` returns for its stored filter right now. "Validated" (`met = "met"`, architecture.md section 3, workflow step 1.3) ships as a built-in smart list, seeded once per user like the default auto-tag rules, recorded in `settings_kv` under `lists.validated_seeded` so a copy the user deletes or renames stays gone. API: `GET/POST /api/v1/lists`, `PATCH/DELETE /api/v1/lists/{id}`, `GET/POST /api/v1/lists/{id}/members`, `DELETE /api/v1/lists/{id}/members/{contact_id}`, and `GET/POST /api/v1/views`, `PATCH/DELETE /api/v1/views/{id}`. CLI: `netkeeper lists list` and `netkeeper lists views`.
