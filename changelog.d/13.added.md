Generic CSV importer with mapping, review, and rollback (`netkeeper.crm.importer`, `netkeeper.crm.import_runs`, `/api/v1/imports`, spec 10.5). Send a CSV and the importer finds its header (the LinkedIn archive's "Notes:" preamble is skipped, header cells are trimmed, a repeated or empty column still gets a key), matches columns to fields by header name through one of the built-in presets — `linkedin-archive`, `linkedhelper`, `nine-column`, each matching a normalized header so `First Name`, `first_name`, and `FIRSTNAME` are one column — and saves any mapping you settle on as a named preset of your own. A draft run stores every row as it was read and resolves the whole file, so the counts are the file's, not a sample's; a preview shows the first twenty resolutions with, per row, whether it is an existing contact, a candidate waiting for your decision, or a new contact, which fields would change, and which are refused because a more authoritative source wrote them — a manual edit above all, which no import overwrites (spec 10.5). Candidates take a `merge_into` or `create_new` decision, and a commit applies the run in one transaction, so the file lands whole or not at all. A row repeated inside the file lands on one contact; a malformed address, an undialable phone number, an unreadable date, or a URL that is not a LinkedIn profile is dropped with its reason on the row while the rest of that row still imports. New `import_runs` and `import_rows` tables record the raw cells, the resolution, the decision, and — this is what makes the undo honest — the value each field held *before* the import, alongside the source and synced-value entries it replaced and the ids of the child rows it added. `POST /imports/{id}/rollback` therefore removes only what that run created: a contact the run created is deleted, a contact it merely enriched keeps the values it had before, a contact the run never touched is left alone, and a field something changed after the import keeps that later value *and its provenance*, so an edit that outlives a rollback is still refused by the next import. A run whose created contacts a merge has since drawn in is refused rather than partly undone, because deleting one of those would take rows the run never created.
