The connections sync now reads what LinkedIn's own connections page loads: it opens the page, scrolls it like a person, and reads the connections the page fetches for itself, without sending, intercepting, or altering any request (ADR 0006). LinkedIn moved the list off the API netkeeper used to call, which is why the first supervised sync found nothing. A page netkeeper cannot read stops the run as `route_changed` and writes none of that page, and a full sync ages nobody unless the page itself proved the end of the list. The fallback that read the page's HTML is no longer used for connections.
