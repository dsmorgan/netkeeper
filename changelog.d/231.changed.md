`make check` resyncs `.venv` before it runs, so a dependency added upstream no longer fails it with an unrecognized pytest argument until `make install` is re-run. uv now always builds `.venv` on a uv-managed CPython rather than the host's own `python3.12`, which in a cloud container is an older patch release than CI's; the first `make install` after pulling this downloads one and rebuilds `.venv`. The `scripts/reset-data.sh` tests skip, with the install command as the reason, where the `sqlite3` command-line tool is missing, except in CI, where they still run.
