The filter language (spec 10.4): `netkeeper.crm.filters` defines the JSON filter tree as Pydantic models (`and`/`or`/`not`; `eq`, `neq`, `contains`, `starts_with`, `is_empty`, `gt`, `gte`, `lt`, `lte`, `between` over an allowlist of contact columns; `has_email`, `has_phone`, `has_li_url`, `has_position`, `email_contains`; `last_contacted`, `connected_within_days`, `changed_jobs_within_days`; and placeholders for `tag_any`/`tag_all`/`tag_none`, `list_member`, `enrolled_in`, `replied_in` that parse now and compile once their tables exist) and compiles it to scoped SQLAlchemy statements (`compile_filter`, `compile_count`, `compile_update`) with `apply_sort`, `paginate`, and a `describe` reading for list headers. Every leaf is two-valued, so `not` is an exact complement; string comparisons are case-insensitive with `%` and `_` matched literally; merged-away contacts never appear and archived ones need `include_archived`. Invalid trees raise one `FilterError` with a JSON path per problem. The tree's JSON schema is snapshotted at `tests/snapshots/filter_schema.json` for the frontend builder; regenerate it with `UPDATE_SNAPSHOTS=1 .venv/bin/python -m pytest tests/test_filters.py`.
